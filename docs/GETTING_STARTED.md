## 1. Читать хаб openradar.fun

Ничего ставить не нужно: откройте [openradar.fun](https://openradar.fun).

- **Без входа** лента показывается с задержкой 12 часов и без контактов. Этого хватает, чтобы понять, что за заказы сюда попадают.
- **Войти через GitHub** — задержка 3 часа и контакты заказчиков. Можно голосовать: «Полезно», «Мусор», «Скам», «Закрыто». Голоса скрывают спам у всех. В меню «Профиль» видно свой уровень, задержку и как подняться выше.
- **Без задержки** лента видна тем, кто сам присылает заказы в сеть (сценарии 4 и 5). Уровни и очки описаны в [PROTOCOL.md](PROTOCOL.md).

Что ещё есть на сайте:

- поиск по тексту, «Заказы / Вакансии» и фильтры: сначала новые, лучшие или дорогие, бюджет от суммы, навык, язык объявления, только удалённо; внизу — «Показать ещё». Ссылку с фильтрами можно сохранить, а кнопка RSS даёт ленту с теми же фильтрами;
- рейтинг у каждого заказа: от 0 до 100, медиана около 60, от 80 — сильный заказ. Как он считается — в [ARCHITECTURE.md](ARCHITECTURE.md#8a-рейтинг-заказа);
- категории в подвале: разработка, Python, боты, 1С, дизайн, тексты и другие;
- RSS: `https://openradar.fun/feed.rss` для любой RSS-читалки;
- «Добавить по ссылке»: вставьте ссылку на заказ, и он попадёт в общую ленту (после входа).

## 2. Узел на своём компьютере

Свой узел — это своя лента без задержек, свои источники и фильтры. Нужны Node.js 22.19+ и pnpm 11+.

```bash
git clone https://github.com/MikhailSagalaev/openradar.git
cd openradar
pnpm install
pnpm dev serve
```

1. В консоли появится строка `токен администратора на этот запуск: …`. Скопируйте токен.
2. Откройте `http://127.0.0.1:8787`, нажмите «Войти» → «Войти по токену».
3. Перейдите в «Источники» → **«Каталог площадок»**. Там FL.ru, Хабр Карьера, Kwork, Freelancehunt, hh.ru, Работа России, публичные Telegram-каналы, We Work Remotely, Jobicy, RemoteOK, ATS-доски компаний и другие. Подключайте по одной кнопкой «Подключить» или все сразу — «Подключить все». Подключённые площадки сразу опрашиваются, первые заказы появятся через несколько секунд.
4. Дальше узел сам опрашивает источники раз в 5 минут (`RADAR_POLL_INTERVAL_SEC`).

**Фильтры.** Откройте источник: «Обязательные слова» (заказ без них отклоняется), «Стоп-слова», город. Каждому заказу считается рейтинг от 0 до 100, в ленте видно, почему он такой: «прямой заказчик», «вилка в рынке» и так далее.

**Уведомления в Telegram.** Создайте бота у [@BotFather](https://t.me/BotFather), узнайте ID своего чата и добавьте в `.env`:

```bash
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_CHAT_ID=123456789
```

Новые заказы будут приходить в чат. Вместо Telegram или вместе с ним можно отправлять их на свой адрес: `WEBHOOK_URL` и `WEBHOOK_SECRET`.

**Данные.** Без `DATABASE_URL` всё хранится в памяти и пропадает при перезапуске. Это удобно, чтобы попробовать. Для постоянной работы нужен PostgreSQL — проще всего через Docker (сценарий 3, он работает и на домашнем компьютере).

**Постоянный токен.** Чтобы токен не менялся при каждом запуске, задайте его в `.env`:

```bash
pnpm init:env    # создаст .env со случайными токеном, паролем базы и секретом веб-ключей
```

Токен для входа — строка `RADAR_ADMIN_TOKEN` в `.env`. Существующий `.env` команда не перезаписывает.

**Командная строка.** Всё, что есть в интерфейсе, доступно и в консоли: `pnpm dev --help`. Например, `pnpm dev leads`, `pnpm dev stats`, `pnpm dev export --format csv`.

## 3. Свой сервер

Нужен Linux-сервер с Docker и Docker Compose.

```bash
git clone https://github.com/MikhailSagalaev/openradar.git /opt/radar
cd /opt/radar
node scripts/init-env.mjs    # .env со случайными секретами; pnpm на сервере не нужен
```

Команда заполнит `RADAR_ADMIN_TOKEN`, `POSTGRES_PASSWORD` (тот же пароль — в `DATABASE_URL`) и `RADAR_WEB_KEY_SECRET`. Вручную в `.env` остаётся задать `RADAR_PUBLIC_URL` — адрес вашего сайта.

Запуск:

```bash
docker compose run --rm radar migrate
docker compose up -d
curl http://127.0.0.1:8787/health
```

Если копировать `.env.example` вручную, замените в нём секреты: с примерами Docker Compose не запустится, это сделано намеренно.

**Домен и HTTPS.** Приложение слушает только `127.0.0.1:${RADAR_HOST_PORT}`. Наружу его открывает nginx: пример в [nginx.example.conf](nginx.example.conf), сертификат — `certbot --nginx -d ваш-домен`.

**Обновление.** [deploy-server.sh](../deploy-server.sh) обновляет код, делает резервную копию базы, применяет миграции и перезапускает приложение:

```bash
RADAR_DIR=/opt/radar bash deploy-server.sh                    # последний main
RADAR_DIR=/opt/radar RADAR_REF=v0.8.0 bash deploy-server.sh   # конкретный релиз
```

**Автообновление по релизам.** [scripts/autodeploy.sh](../scripts/autodeploy.sh) из cron сам выкатывает новый тег `vX.Y.Z`, как только он появится в репозитории. Серверу не нужен ключ от GitHub, а GitHub — ключ от сервера:

```cron
*/5 * * * * root RADAR_DIR=/opt/radar /opt/radar/scripts/autodeploy.sh >> /var/log/radar-autodeploy.log 2>&1
```

Откат: записать нужный тег в `/opt/radar/.deploy-pin`; снять закрепление — удалить файл.

**Резервные копии** по расписанию: [BACKUP_AND_RESTORE.md](BACKUP_AND_RESTORE.md).

**Публичная лента.** `RADAR_PUBLIC_READ=true` открывает ленту без входа. `RADAR_MODE=hub` включает режим хаба: задержки по уровням и скрытые контакты для гостей. Для обычного узла оставьте `node`.

**Аналитика и вебмастера** (по желанию): `RADAR_YANDEX_METRIKA_ID`, `RADAR_GA_ID`, `RADAR_GOOGLE_SITE_VERIFICATION`, `RADAR_YANDEX_VERIFICATION` в `.env`. Без них сайт не обращается ни к каким сторонним счётчикам.

**Вход через GitHub** для посетителей: создайте OAuth App на [github.com/settings/developers](https://github.com/settings/developers) с адресом возврата `https://ваш-домен/auth/github/callback` и заполните `GITHUB_CLIENT_ID` и `GITHUB_CLIENT_SECRET`.

## 4. Telegram через свой аккаунт

Публичные каналы читаются без аккаунта (тип «Telegram»). Закрытые каналы и чаты, где вы состоите, — через свой аккаунт (тип «Telegram (свой аккаунт)»).

1. Получите `api_id` и `api_hash` на [my.telegram.org/apps](https://my.telegram.org/apps) и впишите в `.env`: `RADAR_TELEGRAM_API_ID`, `RADAR_TELEGRAM_API_HASH`.
2. Войдите один раз: `pnpm dev telegram login` (на сервере — `docker compose run --rm -it radar telegram login`). Введите телефон, код из Telegram и пароль двухэтапной проверки, если он есть. Команда напечатает строку `RADAR_TELEGRAM_SESSION=...` — вставьте её в `.env` и перезапустите узел. Это полный доступ к аккаунту: строка живёт только в `.env`.
3. Посмотрите, что можно читать: `pnpm dev telegram chats` выведет каналы и чаты с их `@именем` или числовым ID.
4. В **Источниках** добавьте «Telegram (свой аккаунт)» и перечислите чаты через запятую. Узел читает только новые сообщения, не короче 30 символов; автор сообщения становится контактом.

Второй аккаунт: сессия в `RADAR_TELEGRAM_SESSION_ИМЯ`, это имя — в настройках источника. Не добавляйте десятки чатов в один источник и не ставьте интервал короче 5 минут: Telegram ограничивает аккаунты, которые читают слишком часто. Посты из закрытых чатов станут видны в ленте вашего узла, поэтому берите только чаты для заказов и вакансий.

## 5. Подключить свой парсер

Любой скрипт — Telethon для закрытых каналов, Playwright, cron с curl — может отправлять заказы на узел. Узел нормализует их, склеивает дубли, извлекает контакты и считает рейтинг.

1. Создайте webhook-источник и сохраните id и токен, которые он напечатает:

   ```bash
   pnpm dev source add --kind webhook --title "Мой парсер"
   ```

2. Отправляйте наблюдения. Обязательны только `source.platform`, `source.channel` и `text`:

   ```bash
   curl -X POST http://127.0.0.1:8787/api/v2/ingest/<id> \
     -H "x-radar-token: <токен>" -H "content-type: application/json" \
     -d '[{"source": {"platform": "telegram", "channel": "-1001234567890", "message_id": "48213"},
           "text": "Ищем React-разработчика, удалённо, 250 000 ₽. Пишите @irina_hr"}]'
   ```

   Или потоком из скрипта, по одному JSON на строку:

   ```bash
   python my_parser.py | pnpm dev push --source <id>
   ```

В ответе для каждого наблюдения будет `accepted`, `duplicate` или `rejected` с причинами. Полный формат — в [PROTOCOL.md](PROTOCOL.md). Для Python есть готовый клиент с помощниками для Telethon и Pyrogram: [sdk/python](../sdk/python/README.md).

## 6. Делиться с хабом и получать рейтинг

Кто присылает заказы в общую сеть, тот видит ленту хаба раньше остальных. Очки начисляются за заказы, которые вы увидели первым и которые подтвердились; за закрытые каналы — в полтора раза больше. За скрытый мусор и скам очки снимаются.

**Получите ключ участника.** К нему привязан рейтинг, храните его в секрете:

```bash
pnpm dev key
```

**Вариант А: со своего узла.** Добавьте в `.env`:

```bash
RADAR_HUB_URL=https://openradar.fun
RADAR_NODE_KEY=nsec1...
```

Затем отметьте источники, которыми готовы делиться: галочка в форме источника или `pnpm dev source share <id>`. Остальные источники остаются только у вас. Если хаб недоступен, узел повторит отправку позже.

**Вариант Б: напрямую из парсера**, без своего узла:

```python
import os
from openradar import HubClient, Key

hub = HubClient("https://openradar.fun", Key.from_string(os.environ["RADAR_KEY"]))
hub.observe([{"source": {"platform": "telegram", "channel": "-1001234567890", "visibility": "private", "message_id": "48213"},
              "text": "Ищем React-разработчика..."}])
```

Установка: `pip install "git+https://github.com/MikhailSagalaev/openradar#subdirectory=sdk/python"`.

**Привяжите GitHub**, чтобы рейтинг ключа и аккаунт на сайте были одним участником: `/v2/link/github` (описано в [PROTOCOL.md](PROTOCOL.md)).

## 7. Расширение браузера

Сохраняет заказ или вакансию с любой страницы в общую базу: кнопкой, через контекстное меню или `Alt+Shift+R`. Кнопка «Оценить оплату на рынке» показывает, сколько обычно платят за похожую работу и в рынке ли оплата на этой странице. Работает в Chrome, Edge, Яндекс Браузере и Brave.

1. Скачайте архив на [openradar.fun/extension](https://openradar.fun/extension), распакуйте.
2. Откройте страницу расширений (`chrome://extensions/`, в Яндекс Браузере `browser://extensions/`), включите режим разработчика, нажмите «Загрузить распакованное расширение» и выберите папку.
3. В попапе нажмите **«Войти через GitHub»** и разрешите расширение на сайте. Адрес сервера и токены вводить не нужно: заказы добавляются от вашего имени.

Распакованное расширение само не обновляется: актуальная версия написана на `/extension`, установленная — на странице расширений. Чтобы обновить, распакуйте новый архив поверх старой папки и нажмите «Обновить» на карточке расширения. Свой сервер вместо общей базы — раздел «Свой узел» в попапе. Подробнее — [EXTENSION.md](EXTENSION.md).

## 8. MCP-сервер

Узел умеет работать как MCP-сервер (Model Context Protocol): любая программа с поддержкой MCP может искать заказы (`search_leads`), открывать их (`get_lead_details`) и смотреть статистику рынка (`get_market_analytics`). Правила доступа те же, что в ленте.

`search_leads` отдаёт по 10 лучших результатов в коротком виде и `next_offset` для следующей страницы, чтобы агент не читал всю базу. Фильтры: `query`, `type` (job, gig), `market` (ru — русскоязычные площадки, intl — остальные), `remote`, `skills`, `min_budget_rub`, `since` («24h», «7d» или дата), `sort` (new, score, budget). Полный текст и контакты — `get_lead_details`.

Хаб openradar.fun подключается напрямую: адрес MCP-сервера `https://openradar.fun/mcp`. В Claude: **Настройки → Коннекторы → Добавить свой коннектор**, адрес `https://openradar.fun/mcp`, без входа. В Claude Code: `claude mcp add --transport http openradar https://openradar.fun/mcp`. Описание сервера для реестра MCP — [server.json](../server.json).

Локально, через stdio (сначала `pnpm build`). Пример конфигурации MCP-клиента:

```json
{
  "mcpServers": {
    "openradar": {
      "command": "node",
      "args": ["/путь/к/openradar/bin/radar.js", "mcp"],
      "env": { "DATABASE_URL": "postgres://..." }
    }
  }
}
```

Удалённо, по HTTP: `POST /mcp` на вашем узле или на хабе.

## 9. Написать адаптер

Новая площадка — это один модуль, одна фикстура и один тест. Заготовку создаёт генератор:

```bash
pnpm new:connector mysite
```

Правила адаптеров — в [PLUGINS.md](PLUGINS.md), процесс ревью — в [CONTRIBUTING.md](../CONTRIBUTING.md). Хотите площадку, но не готовы писать код — откройте issue по шаблону «Source request».

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Источник Telegram с ошибкой «Сбой сети» | `t.me` недоступен с сервера. Задайте прокси в `RADAR_PROXY_URL`. |
| Источник `hh` (Open API) находит 0 | hh.ru блокирует API с IP дата-центров. Используйте готовый RSS-источник HeadHunter или токен API. |
| `FATAL: RADAR_ADMIN_TOKEN is missing` | В production токен обязателен и не короче 32 символов. |
| Docker Compose ругается на `.env` | Пароли и токен всё ещё взяты из `.env.example`. Создайте `.env` заново: `node scripts/init-env.mjs --force`. |
| Состояние узла | `GET /health` и вкладка «Источники»: статус, последняя ошибка и счётчики за 24 часа. |
