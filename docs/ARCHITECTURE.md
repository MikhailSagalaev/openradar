# Архитектура Radar

Статус: v0.8 (radar/2). Документ описывает конвейер одного узла. Сеть «узлы → хаб» описана в [PROTOCOL.md](PROTOCOL.md).

## 1. Задача

Radar — самостоятельный сервис, который превращает разрозненные публичные заказы в один нормализованный поток лидов:

```
источник → нормализация → дедуп → качество → правила → (опционально LLM) → рейтинг → доставка
```

Он не является ни парсером «всего интернета», ни SaaS. Ценность — в трубе и контрактах, а не в количестве площадок. Общая лента (хаб) — тот же код в режиме `RADAR_MODE=hub`, куда узлы и парсеры присылают наблюдения сами.

### Не-цели

- обход авторизации, CAPTCHA и платного доступа: закрытые каналы читаются только через аккаунт самого участника, вне узла;
- автоматические отклики и переписка с заказчиками;
- коммерческий доступ к ленте: платные уровни, продажа контактов или откликов;
- гарантия полноты источника;
- мобильное приложение и мультитенантность узла.

## 2. Принципы

1. **Ядро не знает про источники.** Источник — адаптер с маленьким контрактом.
2. **Сначала правила, потом LLM.** Без ключа и без сети классификатор просто выключен.
3. **PostgreSQL 17 и Outbox Pattern.** Выделенная СУБД с pgvector и гарантированной доставкой.
4. **Дедуп объяснимый.** Канонический URL, хэш текста и ключ заголовка, а не «магия».
5. **Данные у оператора.** Self-hosted, без телеметрии и облачной БД.
6. **Легальность по дизайну.** Адаптер обязан объявить уровень доступа и риски.
7. **Ошибка источника не роняет сервис.** Пишется в `runs`, источник продолжает жить.

## 4. Поток данных

1. **Poll.** Планировщик или CLI вызывает `adapter.poll(source, ctx)`.
2. **RawLead.** Адаптер возвращает массив сырых объектов: заголовок, текст, URL, дата, автор, бюджет.
3. **Prepare.** `prepareRawLead` чистит HTML и эмодзи, канонизирует URL, извлекает бюджет и город, считает `fingerprint` и `titleKey`.
4. **Dedup.**
   - точное совпадение `fingerprint` (канонический URL или хэш текста);
   - совпадение `titleKey + city` за последние 24 часа (кросс-источниковый дубль).
5. **Rules.** Спам-паттерны, include/exclude-ключевики, минимальный бюджет, возраст, строгий город.
6. **LLM (опционально).** Если включён и есть ключ: `isLead`, `confidence ≥ 0.6`; при ошибке — продолжаем по правилам.
7. **Store.** Лид пишется со статусом `new` или `rejected`; уникальные индексы защищают от гонок.
8. **Deliver.** Синки получают лид; каждый результат пишется в `deliveries`; итог — `delivered` или `failed`.
9. **Run.** Итоги опроса пишутся в `runs` для диагностики.

## 5. Контракты

### Источник

```ts
interface SourceAdapter {
  kind: 'rss' | 'telegram' | 'telegram-account' | 'kwork' | 'webhook' | 'imap' | 'trudvsem' | 'hh' | 'remoteok';
  access: 'official' | 'public' | 'user-provided' | 'auth-required';
  description: string;
  risks: string[];
  poll?(source: SourceRecord, ctx: PollContext): Promise<RawLead[]>;
}
```

`poll` отсутствует у webhook-источника: данные приходят через `POST /api/ingest/:sourceId`.

### Синк

```ts
interface SinkAdapter {
  kind: string;
  /** Необязательный фильтр: false — лид не ставится в очередь этого синка. */
  accepts?(lead: Lead, source: SourceRecord): boolean;
  deliver(lead: Lead, ctx: SinkContext): Promise<void>;
}
```

### Хранилище

`Store` — интерфейс из `src/core/store.ts`. Production реализация построена на PostgreSQL 17 с pgvector, миграциями через advisory lock и Transactional Outbox Pattern для надёжной доставки. Для изолированных тестов используется In-Memory реализация `MemoryStore`.

## 6. Модель данных

```
sources(id, kind, title, enabled, config_json, created_at, updated_at)
leads(id, source_id, external_id, url, canonical_url, title, text, author,
      city, budget, type, fingerprint, title_key, status, score,
      votes_up, votes_down, votes_scam, votes_closed, quality_score,
      reasons_json, created_at, delivered_at)
lead_votes(user_id, lead_id, signal, weight, counted_at, created_at)
app_users(id, tg_id, github_id, handle, role, reputation, created_at, banned_at)
deliveries(id, lead_id, sink, status, error, created_at)
lead_deliveries(lead_id, sink, status, attempts, next_attempt_at, last_error)
runs(id, source_id, started_at, finished_at, found, inserted,
     duplicates, rejected, delivered, error)
sessions(id, user_id, created_at, expires_at)
```

Таблицы хаба radar/2 (`RADAR_MODE=hub`): `participants`, `events`, `observations`, `lead_contacts`, `signals`, `rating_ledger`, `lead_decisions`, `contact_flags`, `auth_replay`. Их смысл и правила — в [PROTOCOL.md](PROTOCOL.md), схема — в `migrations/011`–`013`.

Индексы:

- `UNIQUE(fingerprint)` и `UNIQUE(source_id, external_id)` — двухуровневый дедуп;
- `PRIMARY KEY (user_id, lead_id, signal)` в `lead_votes` — один голос на участника;
- `(status, created_at)`, `(source_id, created_at)`, `(title_key, created_at)`, GIN по `tsvector` — выборки и поиск.

`config_json` и `reasons_json` — JSON. Секреты в БД не хранятся: только имена переменных окружения и токены вебхуков. Таблицы `app_users`, `lead_votes` и колонка `leads.embedding` (halfvec) — задел под Этапы 3–4 роадмапа; эмбеддинги пока не заполняются.

## 7. Источники: политика

| Тип | Доступ | Что делает | Риски |
|---|---|---|---|
| RSS | official | читает фид | почти нет; зависит от фида |
| IMAP | user-provided | читает письма-оповещения | пароль в env; письма теряют вёрстку |
| Telegram public | public | `t.me/s/<channel>` | вёрстка, лимиты, неполная история |
| Telegram account | user-provided | каналы и чаты своего аккаунта через MTProto (mtcute), в том числе закрытые | сессия в env; частый опрос может ограничить аккаунт; посты закрытых чатов попадают в ленту узла |
| Kwork | public | `window.stateData` | вёрстка, условия площадки |
| Webhook | user-provided | входящий JSON | доверие к отправителю |
| Browser extension | user-provided | отправляет страницу в webhook | токен хранится в браузере |

Правила для нового адаптера:

1. Никакого обхода логина, CAPTCHA, платных стен и приватных групп.
2. Объявить `access` и `risks` в коде.
3. Уважать `RADAR_HTTP_TIMEOUT_MS` и не делать больше одного запроса на источник за тик.
4. Не хранить чужие cookies и сессии в репозитории.
5. Приложить фикстуру и тест: адаптер без теста не принимается.

## 8. Синки

- `console` — по умолчанию, удобно для первого запуска.
- `telegram` — `sendMessage` с HTML и ссылкой на источник.
- `webhook` — JSON `{ event: "lead.created", lead }`, опциональный `x-radar-secret`.
- `hub` — узел → хаб: лиды источников с флагом `share` подписываются ключом `RADAR_NODE_KEY` и уходят в `RADAR_HUB_URL` как наблюдения kind 4040. Повторы — через outbox.

Синк не имеет права ронять пайплайн: ошибка ловится, пишется в `deliveries` и `lastError` лида.

## 8a. Рейтинг заказа

`scoreLead()` в `src/core/rules.ts` считает статичную ценность лида от 0 до 100 один раз, при приёме. Свежесть в него не входит: при приёме свежий каждый лид, а порядок по времени даёт сама лента.

| Сигнал | Баллы |
| --- | --- |
| База | 55 |
| Деньги, в долларах по курсу из `salary.ts`: заказ — по сумме (< $15 → −8, ≥ $1500 → +22); вакансия и почасовая ставка — по месячной сумме (< $700 → −5, ≥ $3300 → +20) | −8…+22 |
| Навыки в тексте (разработка, дизайн, видео, тексты, реклама, маркетплейсы, бухгалтерия…): 1 / 2 / 3+ | +6 / +9 / +12 |
| Ключевые слова источника (`includeKeywords`) | +8 за слово, до +24 |
| Подробность текста: < 60 знаков / < 150 / > 600 / > 1500 | −10 / −4 / +4 / +6 |
| Прямой контакт в тексте | +3 |
| Пост старше недели к моменту приёма | −10 |
| Город источника / «Онлайн», доверие источника (`trust`) | +5 / +2, до +10 |

Голоса участников добавляют поправку поверх базы (`recalculateVoteScoreAndStatus`). На лидах хаба медиана около 60, 90-й перцентиль около 73, от 80 — примерно каждый двадцатый. После смены формулы `radar rescore` пересчитывает сохранённые лиды, голоса сохраняются.

Порядок «Сначала лучшие» — рейтинг минус 4 балла за каждые сутки возраста (`SCORE_DECAY_PER_HOUR`).

## 8b. Качество поста

Стадия качества (`src/core/quality.ts`) идёт перед правилами. Правила отклоняют спам целиком. Флаг качества пост оставляет, но опускает его в ленте и объясняет почему: ленте, API (`qualityFlags`) и MCP (`flags`).

| Флаг | Что это | Штраф к рейтингу |
| --- | --- | --- |
| `channel_ad` | реклама или контент канала: продажа курса, поток, вебинар, акция, статья с вопросом в заголовке | −50 |
| `mlm` | «с нас обучение», возраст 19–40, «без вложений», «выведем на фриланс» | −40 |
| `digest` | подборка из нескольких вакансий в одном посте | −20 |
| `outstaff` | аутстафф: исполнителя нанимает посредник | −10 |

Флаг не ставится, если в посте явно нанимают («#вакансия», «ищем», «требуется») или есть три признака вакансии: пост с рекламной строкой в подвале остаётся вакансией. Маркировка рекламы (erid) — тоже не флаг: работодатели платят каналам за размещение вакансий.

Ещё стадия исправляет тип у постов без своего типа (Telegram, вебхук). Вакансией считается пост с двумя признаками вакансии («Зарплата:», «на руки», «полная занятость», «опыт работы:», «О нас:», уровень junior–senior и т. п.) без признаков разовой задачи («нужно сделать», «ТЗ», «бюджет:»). Вакансией считается и пост, который начинается с роли в представленной компании: «Аналитик в X — IT-компания…».

`radar requality --days 60` заново прогоняет стадию качества и рейтинг по сохранённым лидам. Голоса сохраняются.

## 8c. Подписки (сохранённые поиски)

Вошедший через GitHub пользователь нажимает «Следить» в ленте. Подписка берёт ровно фильтры на экране: запрос, тип, «Только IT», «Только удалённо», бюджет, навык, язык. Новые подходящие заказы приходят в Telegram или на вебхук. До 20 подписок на человека.

- **Доставка** (`src/pipeline/subscriptions.ts`) идёт в фоновом цикле. Каждая подписка проверяется не чаще раза в 15 минут, в одном сообщении до 10 заказов и ссылка на остальные.
- **Задержка уровня соблюдается.** Новые заказы берёт та же функция, что строит ленту этому пользователю. Курсор подписки двигается до момента, который пользователь уже может видеть, поэтому подписка не обходит задержку.
- **Курсор при сбоях.** Неудачная отправка курсор не двигает, следующий круг повторяет её. После 10 сбоев подряд подписка встаёт на паузу. После паузы или долгого простоя приходят заказы не старше 3 дней.
- **Telegram:** бот хаба (`TELEGRAM_BOT_TOKEN` и `RADAR_SUBSCRIPTION_BOT=true`). Он читает свои сообщения длинным опросом (`getUpdates`), то есть исходящим запросом. Telegram не нужно достучаться до хаба, а у хаба нет входящего адреса для бота. Если задан `RADAR_PROXY_URL`, вызовы Bot API идут через него: из России `api.telegram.org` напрямую недоступен. В профиле «Подключить Telegram» открывает `t.me/<бот>?start=<код>`: код одноразовый, живёт час, привязываются только личные чаты. `/stop` отвязывает чат. Если пользователь заблокировал бота, чат забывается.
- **Вебхук:** `POST` с JSON `{ event: "subscription.leads", subscription, leads, more, manage_url }`. Принимаются только https-адреса в интернете: адрес проверяется SSRF-защитой при сохранении и перед каждой отправкой. Заголовки:
  - `X-OpenRadar-Timestamp` — секунды Unix;
  - `X-OpenRadar-Signature: sha256=<hex>` — HMAC-SHA256 от `«timestamp.body»` секретом подписки. Секрет виден владельцу в профиле.

Проверка подписи на стороне получателя (Node.js):

```js
const expected = 'sha256=' + crypto.createHmac('sha256', SECRET).update(`${req.headers['x-openradar-timestamp']}.${rawBody}`).digest('hex');
const ok = crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(req.headers['x-openradar-signature']));
```

## 9. LLM

- Включается только `RADAR_LLM_ENABLED=true` и наличием API-ключа.
- Любой стандартный endpoint: внешний шлюз или локальный сервис с HTTP API.
- Ответ — строгий JSON; текст лида передаётся как данные, не как инструкции.
- Ошибка/таймаут → `null`, пайплайн продолжает по правилам.
- Модель не влияет на дедуп и не может «оживить» отклонённый спам.

## 10. Runtime

### CLI

`init`, `migrate`, `source add/list/share/enable/disable/remove`, `poll`, `run`, `serve`, `leads`, `runs`, `stats`, `export`, `push` (NDJSON-наблюдения из stdin), `key` (ключ участника), `rescore` (пересчёт рейтинга заказов), `requality` (заново тип, флаги качества и рейтинг), `mcp`.

### HTTP

- `GET /health` — публичный.
- `GET /auth/github` и `GET /auth/github/callback` — OAuth-вход через GitHub; сессия в HttpOnly-cookie.
- `GET /` — лента с поиском и фильтрами: тип, `sort=new|score|budget` (лучшие и дорогие — за последние 7 дней), `budget` (от суммы в рублях), `skill`, `language=ru|en` (язык заголовка), `remote=1`, `it=1` (только IT-работа, список навыков — `IT_SKILLS` в `src/server/filters.ts`), `page` (по 50 лидов). Те же параметры принимают `/api/leads`, `/feed.rss` и `/v2/feed` (в `/v2/feed` курсор работает только с `sort=new`). Фильтр по статусу воронки и отклонённые лиды видит только админ.
- `GET /leads/:id` — карточка лида: полный текст, источник, рейтинг, причины.
- `POST /leads/:id/vote` и `POST /api/leads/:id/vote` — голосование; только пользователь с GitHub-входом, один голос на сигнал.
- `POST /leads/:id/status`, `POST /leads/:id/feedback`, `PATCH /api/leads/:id/status` — воронка; только админ.
- `GET /submit`, `POST /submit`, `POST /api/submit`, `POST /api/preview` — добавление по ссылке; запись — только после GitHub-входа, превью ходит через SSRF-guarded fetch.
- `GET /feed.rss`, `/feed.xml`, `/api/feed.rss` — RSS-лента под запрос.
- `GET /catalog/:slug` — индексируемые страницы категорий; `GET /robots.txt`, `GET /sitemap.xml` — в sitemap попадают категории и лиды, которые видит гость.
- `GET /extension`, `GET /extension/download` — страница и архив браузерного расширения.
- `GET /api/market?title=&type=job|gig&skills=` — оценка оплаты для расширения: 25/50/75-й перцентили по похожим лидам с бюджетом за 90 дней (похожие — где есть половина слов запроса по основам или половина навыков; меньше трёх — по всем лидам типа). Только агрегаты по лидам, которые уже видит гость; `Access-Control-Allow-Origin: *`.
- `GET /admin` — сводка для оператора: заказы по дням, источники за неделю, пользователи, голоса, участники сети. Админ — токен `RADAR_ADMIN_TOKEN` или GitHub-аккаунт из `RADAR_ADMIN_GITHUB`.
- `GET|POST /extension/connect`, `/api/ext/me`, `/api/ext/submit`, `DELETE /api/ext/token` — вход расширения через GitHub: токен `ext_…` только на добавление заказов, хранится SHA-256, возвращается лишь на `https://<id>.chromiumapp.org/`.
- `GET /me` — профиль вошедшего: уровень, задержка, рейтинг привязанного ключа, как подняться.
- `GET /yandex_<код>.html` — подтверждение Яндекс Вебмастера, если задан `RADAR_YANDEX_VERIFICATION`. Счётчики Метрики и Google Analytics и мета-тег Search Console выводятся только при `RADAR_YANDEX_METRIKA_ID`, `RADAR_GA_ID`, `RADAR_GOOGLE_SITE_VERIFICATION`; CSP расширяется на их домены только тогда же.
- `GET /og.png` — карточка для соцсетей; `og:image` и абсолютный `og:url` выводятся, когда задан `RADAR_PUBLIC_URL`.
- `GET /assets/app.<hash>.css`, `GET /assets/logo.<hash>.svg` — стили и логотип с годовым кэшем; хэш меняется вместе с содержимым.
- `GET /api/delta` — поток изменений для синхронизации узлов (JSON/NDJSON).
- `GET /sources`, `/sources/new`, `/sources/:id`, `/sources/:id/edit` — дашборд источников.
- `POST /sources`, `POST /sources/:id`, toggle/delete — управление; только админ.
- `/api/*` — чтение: токен, GitHub-сессия или `RADAR_PUBLIC_READ`; управление источниками: только админ.
- `/api/ingest/:sourceId` — админский токен или токен источника.
- `/api/v2/ingest/:sourceId` — наблюдения radar/2 (до 500, JSON или NDJSON), тот же доступ.
- `/v2/*` — API хаба (`RADAR_MODE=hub`): `events`, `feed`, `stream`, `leads/:id`, `contacts/:value`, `me`, `link/github`, `moderation/*`. Описание — [PROTOCOL.md](PROTOCOL.md).
- `/mcp` — MCP поверх ленты с теми же задержками и правилами контактов.
- Неизвестный путь — HTML-страница 404 для браузера, `{"error":"not_found"}` для `/api`, `/v2`, `/mcp` и запросов без `Accept: text/html`.

### Browser extension

`extension/` — Manifest V3 без сборки. Читает активную вкладку после клика и отправляет `title`, `text`, `url` в webhook-источник. Токен источника хранится в `chrome.storage.local`; это осознанно не синхронизируемый секрет.

### Планировщик

`PollRunner` запускает `pollAll` каждые `RADAR_POLL_INTERVAL_SEC` секунд, не допускает наложения запусков и логирует итоги. `serve --no-scheduler` оставляет только HTTP.

- Источники опрашиваются по `RADAR_POLL_CONCURRENCY` (16) одновременно, сначала те, что ждут дольше всех. Источник может задать `config.intervalSec`, чтобы опрашиваться реже тика. Запуск, не успевший за интервал, перестаёт брать новые источники: они пойдут первыми в следующий раз.
- Доставка из outbox, дайджест, обслуживание и проверка закрытых заказов идут отдельным циклом раз в минуту и не ждут опроса.

### Закрытые заказы и срок жизни

Площадки закрывают заказы и убирают вакансии в архив молча. Узел раз в 5 минут берёт по каждой площадке до 20 активных лидов, чья страница давно не проверялась (первые двое суток — раз в 6 ч, до недели — раз в день, дальше — раз в 3 дня), и открывает страницу на площадке. По одной площадке запросы идут по одному с паузой 3 с; проверка идёт отдельно и не задерживает доставку.

| Площадка | Признак закрытия |
| --- | --- |
| Kwork | `wantData.status` не `active` |
| FL.ru | 404, иконка «снят с публикации», «Заказ находится в архиве» |
| Хабр Карьера, hh.ru | `"archived": true` в данных страницы |
| We Work Remotely, Jobicy, RemoteOK, Работа России | 404 или 410 |

Закрытый лид получает состояние `closed` (решение `source`), уходит из ленты, а его страница остаётся по ссылке с пометкой «Закрыто». Сетевая ошибка или блокировка ничего не закрывает. Что проверить нельзя (Telegram, почта, площадки, закрытые от ботов), уходит из ленты по возрасту: заказы через `RADAR_GIG_TTL_DAYS` (14) дней, вакансии через `RADAR_JOB_TTL_DAYS` (30); 0 выключает предел. Рыночная оценка считает и по старым лидам. Выключить проверку: `RADAR_CHECK_CLOSED=false`.

## 11. Безопасность

- Секреты только в env; `.env` в `.gitignore`.
- Авторизация: админ-токен (минимум 32 символа в production) и GitHub OAuth (`read:user`, state-проверка) для участников. Сессии в HttpOnly/SameSite-cookie; сессия пользователя не даёт админских прав.
- SSRF: исходящие запросы (`fetchText`, `fetchSafeHttp`) резолвят DNS и блокируют приватные/метаданные-адреса на каждом редиректе; `/api/preview` ходит через тот же guard. Известное ограничение (аудит C1): фильтр стоит заменить поддерживаемой библиотекой.
- Вебхук: отдельный токен на источник, лимит 100 объектов за запрос.
- Размеры: тело запроса — до 1 МБ, до 10 МБ на `/api/ingest`, `/api/v2/ingest` и `/v2/events`; ответы источников читаются потоком и обрываются после 10 МБ (3 МБ для `/api/preview`). Пример nginx ограничивает частоту запросов с одного IP.
- HTML из источников не рендерится как HTML: только текст и экранирование.
- Prompt injection: текст лида передаётся классификатору как данные, без инструментов и без исполнения.
- Контакты: хранятся структурно (`lead_contacts`); гостям хаба не отдаются ни в одном интерфейсе (страницы, API, RSS, каталог, MCP).
- Хаб: события подписаны (BIP-340), HTTP-запросы — подписью NIP-98 с привязкой к URL, методу и телу, одноразово. Голая подпись ключом даёт уровень гостя.

## 12. Легальность

Radar — инструмент, а не разрешение. Ответственность несёт тот, кто запускает сбор.

- Публичная страница не значит «свободно для перепубликации»: действуют права изготовителя базы данных, авторские права, 152-ФЗ и правила площадок.
- hh.ru закрыл публичный API вакансий в 2026; Upwork отключил RSS в 2024. Площадки закрывают доступ, а не открывают.
- Поэтому приоритет: RSS, официальные API, письма-оповещения, данные, которые оператор и так получил.
- При требовании площадки источник удаляется из конфигурации узла; на хабе модератор скрывает лиды канала.

## 14. Решения (ADR)

| Решение | Почему |
|---|---|
| Один пакет, а не монорепо | MVP быстрее; границы уже выражены каталогами, выделение в пакеты — механическое |
| PostgreSQL 17 + pgvector | строгая изоляция, параллельная обработка, векторный поиск и outbox |
| Hono, не NestJS | лёгкий HTTP-слой без декораторов и DI-контейнера |
| Правила до LLM | работает без ключа и без сети, объяснимо и дешево |
| Нет автопубликации | сбор и доставка отделены от решения человека |
| AGPL-3.0 | сервис остаётся открытым, включая сетевые форки |
| Webhook как источник | «принеси свои данные» — легальная альтернатива скрейпингу |

## 15. Как добавить адаптер

1. Создать `src/sources/<name>.ts` с объектом `SourceAdapter`.
2. Зарегистрировать его в `src/sources/index.ts`.
3. Добавить фикстуру в `test/fixtures/`.
4. Добавить тест в `test/sources.test.ts`: парсинг, пустой ответ, ошибка HTTP.
5. Описать доступ и риски в `risks`.
6. Проверить: `pnpm typecheck && pnpm test && pnpm build`.

## 16. Архитектура БД и изоляция (Database per Service)

Radar спроектирован как полностью обособленный сервис:
- **Изоляция данных:** Radar использует собственную выделенную базу данных PostgreSQL 17 с расширением `vector` (`pgvector`).
- **Связь с другими системами только по API:** отправка лидов осуществляется через стандартные Webhook-эндпоинты (`POST /api/ingest/:sourceId`), исключая общие таблицы или прямые SQL-связи.
- **Transactional Outbox:** каждая фиксация лида атомарно создаёт записи поканальной доставки в `lead_deliveries` для надежной доставки без дублей (`FOR UPDATE SKIP LOCKED`).
