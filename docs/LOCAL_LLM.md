# openradar с локальной LLM

Классификатор и извлечение данных для research принимают **любой OpenAI-совместимый
HTTP API** — включая полностью локальные. Сеть для этого не нужна; без ключа и без LLM
всё работает по правилам, LLM только добавляет точность.

## Включение

```bash
RADAR_LLM_ENABLED=true
OPENAI_BASE_URL=http://127.0.0.1:11434/v1   # ollama
OPENAI_MODEL=qwen2.5:7b
OPENAI_API_KEY=ollama                        # любое непустое значение
```

- **[ollama](https://ollama.com)**: `OPENAI_BASE_URL=http://127.0.0.1:11434/v1` после `ollama serve`.
- **[LM Studio](https://lmstudio.ai)**: `http://127.0.0.1:1234/v1`.
- **llama.cpp server**: `http://127.0.0.1:8080/v1`.

Требования к модели: JSON-режим (`response_format: json_object`) и понимание русской речи —
проверены `qwen2.5` от 7B и `llama3.1` от 8B. Классификатор зовётся только для принятых
правилами лидов; таймаут 25 секунд, при ошибке пайплайн продолжает по правилам.

## Внешний провайдер (на примере Groq)

Подойдёт любой OpenAI-совместимый провайдер и любая его модель с JSON-режимом и хорошим
русским — выбор за оператором. Например, [Groq](https://console.groq.com):

```bash
RADAR_EXTRACT_ENABLED=true
RADAR_EXTRACT_PROVIDER=openai
OPENAI_BASE_URL=https://api.groq.com/openai/v1
OPENAI_API_KEY=gsk_...
RADAR_EXTRACT_MODEL=your-model
RADAR_EXTRACT_PER_HOUR=40
```

- Бесплатный тариф Groq — 1 000 запросов в сутки и 8 000 токенов в минуту, это около
  40 постов в час. На HTTP 429 пачка останавливается и ждёт `Retry-After`. Платный
  тариф снимает оба предела, тогда `RADAR_EXTRACT_PER_HOUR` можно поднять до 150–200.
- Groq отвечает 403 российским адресам и выходам Tor. С такого сервера запросы идут через
  ретранслятор на Vercel из `deploy/model-relay` (README там же): `OPENAI_BASE_URL`
  указывает на него, ключ провайдера проходит насквозь и в ретрансляторе не хранится.
- Классификатор (`RADAR_LLM_ENABLED`) спрашивает модель о каждом принятом лиде — это
  тысячи запросов в сутки; сверяйтесь с лимитами своего провайдера.

## Ротация провайдеров извлечения

Эндпоинты можно перечислить пулом `RADAR_EXTRACT_PROVIDERS` (JSON-массив): они пробуются
по порядку, и эндпоинт с ответом 401/402/403 паркуется — следующий извлекает тот же пост.
Припаркованные пробуются снова через `RADAR_EXTRACT_PROVIDER_COOLDOWN_MIN` (по умолчанию 60).
Удобно ставить бесплатные тиры первыми, платные пакеты последними:

```bash
RADAR_EXTRACT_PROVIDERS=[{"baseUrl":"https://free-provider.example/v1","apiKey":"...","model":"free-model","pauseMs":9000,"concurrency":1},{"baseUrl":"https://api.openai.com/v1","apiKey":"sk-...","model":"your-model"}]
```

`pauseMs`/`concurrency` задают темп пачки под лимиты конкретного провайдера (например,
7 запросов в минуту → `pauseMs: 9000, concurrency: 1`). Одиночный провайдер через
`OPENAI_*` работает как раньше и добавляется в конец пула, если его там ещё нет.
GigaChat в пул не входит — у него свой поток токенов и обработка занятости.
В сохранённых фактах записывается модель, реально ответившая на пост.

## Что LLM делает

- `isLead` + `confidence ≥ 0.6` — может отклонить, не может «оживить» спам;
- категория, город, навыки, оценка бюджета — заполняют пустые поля;
- research-извлечение (`RADAR_EXTRACT_ENABLED=true`): зарплата, роль, грейд из постов
  для открытого отчёта — ответ проверяется по полям, разметка страницы и правила приоритетнее модели.

## Безопасность

Текст лида передаётся модели как данные (JSON в `user`-сообщении), без инструментов и
без исполнения. Скрытые Unicode-инструкции в постах вырезаются на приёме. Ответ модели —
строгий JSON; всё остальное отбрасывается.
