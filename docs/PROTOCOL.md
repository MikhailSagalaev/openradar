# radar/2: протокол сети openradar

radar/2 — протокол, по которому любой парсер отдаёт наблюдённые вакансии и заказы в один общий хаб. Хаб склеивает их в ленту и даёт ранний доступ тем, кто вносит вклад. Коммерческого слоя нет.

## Роли

- **Парсер** — любой внешний код (Telethon, Playwright, скрапер). Отправляет JSON-наблюдения в свой узел или сразу в хаб через SDK.
- **Узел** — self-hosted `radar` (`RADAR_MODE=node`). Работает автономно. Источники с флагом `share` отправляет в хаб.
- **Участник** — владелец ключа secp256k1. Рейтинг привязан к ключу.
- **Хаб** — `radar` в режиме `RADAR_MODE=hub` (openradar.fun). Принимает события, склеивает лиды, считает рейтинг, раздаёт ленту.
- **Модератор** — ключ из `RADAR_MODERATORS`.

Хаб один. Транспорт — HTTP. Формат событий совместим с Nostr (NIP-01), публичные ретрансляторы не используются: через них ранний доступ невозможен.

## Наблюдение (`radar/2.observation`)

```json
{
  "schema": "radar/2.observation",
  "source": { "platform": "telegram", "channel": "-1001234567890", "channel_title": "Frontend jobs",
              "visibility": "private", "message_id": "48213", "url": null },
  "posted_at": "2026-10-26T11:02:00Z",
  "author": { "name": "Ирина", "handle": "@irina_hr",
              "contacts": [{ "type": "telegram", "value": "@irina_hr" }, { "type": "phone", "value": "+79991234567" }] },
  "title": null,
  "text": "Ищем React-разработчика...",
  "type": "job",
  "budget": { "min": 200000, "max": 300000, "currency": "RUB", "period": "month" },
  "skills": ["react", "typescript"],
  "location": { "city": "Москва", "remote": true },
  "raw": {}
}
```

Обязательны `source.platform`, `source.channel`, `text`. `platform` — `[a-z0-9_.-]{1,32}`. `channel` — стабильный ID, для Telegram числовой `chat_id`. `visibility`: `public` (по умолчанию), `private`, `invite`. Контакты (`telegram`, `phone`, `email`, `whatsapp`, `vk`, `url`, `other`, до 20) нормализуются; если их не передали, они извлекаются из текста. `text` — до 20 000 символов. `raw` в хаб не уходит. Аккаунт, через который читается канал, в схеме не передаётся.

### Приём на узле

`POST /api/v2/ingest/:sourceId` с заголовком `x-radar-token` (токен webhook-источника) или токеном администратора. Тело — JSON-массив, `{"observations": [...]}` или NDJSON, до 500 наблюдений и 10 МБ. Ответ: `received`, `accepted`, `duplicate`, `rejected` и `outcomes` по каждому наблюдению (`leadId`, `reasons`). То же из командной строки: `radar push --source <id>` читает NDJSON из stdin; с `--url` и `--token` отправляет на удалённый узел.

На узле действуют правила склейки 1–3 из раздела ниже.

## События и подпись

Постоянный ключ участника, события NIP-01: `id` = SHA-256 от `[0, pubkey, created_at, kind, tags, content]`, `sig` = BIP-340.

| kind | Имя | content | Теги |
| --- | --- | --- | --- |
| 4040 | observation | JSON наблюдения без `raw` | `v=radar/2`, `src=<platform>,<channel>`, `msg=<message_id>`, `vis=<visibility>` |
| 4041 | signal | комментарий до 500 символов | `lead=<lead_id>`, `signal=useful\|junk\|scam\|closed` |
| 4042 | status | пусто | `src`, `msg`, `status=deleted\|edited\|closed` |

Приём: событие до 64 КБ; `created_at` от −30 дней до +10 минут; наблюдения с `posted_at` старше 48 ч — архив без очков; повтор `id` — `duplicate`.

**Аутентификация запросов** (по мотивам NIP-98): `Authorization: Nostr <base64 события kind 27235>` с тегами `u` (URL), `method`, `payload` (SHA-256 тела); `created_at` ±60 с; повтор того же заголовка отвергается. Публичный ключ сам по себе доступа не даёт.

## Склейка в лиды (хаб)

Правила по порядку, первое совпадение побеждает:

1. Тот же пост: `platform + channel + message_id`.
2. Та же ссылка: канонический URL.
3. Общий контакт и сходство текстов J ≥ 0.6 (MinHash) за 14 дней.
4. Сходство J ≥ 0.85 за 7 дней.
5. Иначе — новый лид.

`created_at` лида — время приёма хабом первого наблюдения. Контакты и источники объединяются. Повторное наблюдение другим участником — подтверждение, в том числе для закрытых каналов без ссылки.

## Рейтинг и уровни

Лид подтверждён, если: его наблюдал другой участник с весом ≥ 0.2, или взвешенные `useful` ≥ 1.0, или он прожил 24 ч без жалоб с суммарным весом ≥ 0.5, а у первого наблюдателя вес ≥ 0.2 (в этом случае половина очков). Ключ без веса подтверждается только чужим наблюдением или голосами, поэтому кольцо свежих ключей не набирает рейтинг само.

| Событие | Очки |
| --- | --- |
| Подтверждённый лид, первым | +1.0 (×1.5 закрытый канал, ×1.5 эксклюзив 6 ч) |
| Подтверждающее наблюдение участника с весом ≥ 0.2 (до трёх) | +0.2 |
| Сигнал совпал с итогом | +0.1 |
| Лид скрыт как junk/scam | −3.0 первому, −0.5 подтвердившим |

R = сумма за 30 дней, не меньше 0; вес сигналов w = min(1, w₀ + R/30), w₀ = 0.2 при GitHub старше 90 дней, 1.0 у модератора.

| Уровень | Условие | Задержка | Контакты |
| --- | --- | --- | --- |
| Гость | без входа | 12 ч | нет |
| Участник | вход или R ≥ 1 | 3 ч | да |
| Активный | R ≥ 10 | 30 мин | да |
| Ядро | R ≥ 50 или модератор | 0 | да |

Ключ без рейтинга и без привязанного GitHub — гость: сгенерировать ключ ничего не стоит, поэтому контакты он не открывает. «Вход» — GitHub-сессия на сайте или ключ, привязанный к GitHub через `POST /v2/link/github`.

Рейтинг пересчитывается раз в час (и по `POST /v2/moderation/recompute`) по журналу начислений; пересчёт идемпотентен. Подтверждение лида запоминается: если вес подтвердившего позже упадёт, очки не отзываются. Голоса на сайте идут в те же сигналы от имени `web:<id пользователя>` с весом по возрасту GitHub-аккаунта и рейтингу привязанного ключа.

Задержки настраиваются: `RADAR_TIER_DELAYS=guest=720,member=180,active=30,core=0` (минуты). На узле (`RADAR_MODE=node`) задержек нет.

## Сигналы и модерация

Один сигнал на участника и лид, новый заменяет старый. Сигналы первого наблюдателя по своему лиду не считаются. Лид скрывается, если J + S ≥ 2.0 и J + S > 2U (`hidden_junk` / `hidden_scam`), или C ≥ 1.5 (`closed`). Скрытие обратимо.

Порядок решений: модератор → контакт, помеченный как мошеннический → закрытие автором (kind 4042) → взвешенные сигналы. Модератор задаётся в `RADAR_MODERATORS` (hex-ключи через запятую) и работает своим ключом с подписью NIP-98; админ-токен хаба тоже допускается.

## API хаба

| Метод | Назначение |
| --- | --- |
| `POST /v2/events` | до 500 событий (массив, `{"events": [...]}` или одно событие), ответ `results` по каждому: `accepted` / `duplicate` / `rejected:<причина>`, для наблюдений `leadId` и `merged` |
| `GET /v2/feed` | лента с задержкой уровня: `limit` (до 200), `type`, `q`, `cursor`, `format=ndjson` |
| `GET /v2/stream` | SSE: события `lead` с `id` = курсор; `cursor` или `Last-Event-ID` продолжают поток |
| `GET /v2/leads/:id` | карточка, наблюдения (ключ, канал, первый ли, архив) и счётчики сигналов |
| `GET /v2/contacts/:value` | история автора по контакту (`@handle`, телефон, email, ссылка); гостям недоступно |
| `GET /v2/me` | ключ, уровень, задержка, профиль (только с подписью Nostr) |
| `POST /v2/link/github` | привязка ключа к GitHub |
| `POST /v2/moderation/lead/:id` | `{state: active\|hidden_junk\|hidden_scam\|closed\|null, reason}`; `null` возвращает лид сигналам |
| `POST /v2/moderation/contact` | `{value, type?, flag: "scam"\|null, reason}`: скрывает все лиды с этим контактом, в том числе будущие |
| `POST /v2/moderation/ban/:pubkey` | `{ban: true\|false, reason}`: забаненный ключ теряет доступ и вес |
| `POST /v2/moderation/recompute` | пересчитать рейтинг сейчас |

## Узел → хаб

На узле задайте `RADAR_HUB_URL=https://openradar.fun` и `RADAR_NODE_KEY` (создаётся командой `radar key`), затем отметьте источник: `radar source share <id>` или галочка в форме источника. Лиды этого источника подписываются ключом узла и уходят в хаб как kind 4040; при недоступности хаба outbox повторяет отправку. Остальные источники остаются только на узле.

## SDK

- **Python** (`sdk/python`, без зависимостей): `Key`, `HubClient` (`observe`, `signal`, `status`, `me`, `feed`, `lead`), `NodeClient.push`, `openradar.telegram` для Telethon и Pyrogram.
- **TypeScript**: `HubClient` и `NodeClient` из пакета (`src/client.ts`).
- **CLI**: `radar push --source <id>` читает NDJSON-наблюдения из stdin.

```python
from openradar import HubClient, Key
hub = HubClient("https://openradar.fun", Key.from_string(os.environ["RADAR_KEY"]))
hub.observe([{"source": {"platform": "telegram", "channel": "-1001234567890",
                         "visibility": "private", "message_id": "48213"},
              "text": "Ищем React-разработчика..."}])
```

Курсор ленты непрозрачный. Первый запрос без курсора возвращает самые новые лиды и курсор на самый новый; следующие запросы с курсором возвращают только более новые, от старых к новым. Курсор приходит в теле (`cursor`) и в заголовке `x-radar-cursor`.

Причины отказа событий: `malformed:<поле>`, `bad_id`, `bad_signature`, `too_large`, `created_at_in_future`, `created_at_too_old`, `unsupported_kind`, `banned`, `content_not_json`, `invalid:<поле>: <ошибка>`, `src_tag_mismatch`, `msg_tag_mismatch`, `not_a_lead`, `bad_signal_tags`, `unknown_lead`, `bad_status_tags`, `profile_not_object`.

Статус `deleted` или `closed` закрывает лид, только если его прислал участник, первым сообщивший о посте. Профиль (kind 30440) — JSON с полями `name`, `about`, `website`, `github`.
