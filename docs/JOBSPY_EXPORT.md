# JobSpy-совместимый экспорт

`radar export --jobspy` выгружает ленту в CSV с колонками, которые ожидают
пайплайны [JobSpy](https://github.com/speedyapply/JobSpy) (pandas DataFrame).
Цель — чтобы пользователи JobSpy заменили прокси-скрейпинг легальной выгрузкой,
не меняя свой код.

```bash
pnpm dev export --jobspy --limit 5000 --out openradar-jobspy.csv
# на проде: node bin/radar.js export --jobspy
```

```python
import pandas as pd
df = pd.read_csv("openradar-jobspy.csv", encoding="utf-8-sig")
print(df[df.SITE == "telegram"].head())
```

## Колонки

| Колонка | Откуда в openradar |
| --- | --- |
| `SITE` | слаг источника: `sourceRef.platform` (например `telegram`), иначе kind источника (`kwork`, `hh`, `remoteok`, …) |
| `TITLE`, `COMPANY`, `DESCRIPTION` | заголовок, автор (когда известен), текст лида до 1500 символов |
| `LOCATION` | город; `Remote`, если города нет и пост удалённый |
| `JOB_TYPE` | `fulltime` для вакансий (`type=job`), пусто для заказов — других типов мы не знаем |
| `INTERVAL` | `monthly` / `hourly` из нормализации зарплаты; годовые зарплаты нормализованы в месячные при приёме |
| `MIN_AMOUNT`, `MAX_AMOUNT`, `CURRENCY` | бюджет лида **в валюте поста** (не USD-нормализованный), `budget` идёт в обе колонки, если вилка одна |
| `JOB_URL` | канонический URL поста |
| `POSTED_AT` | время публикации на источнике, ISO 8601 |

`DESCRIPTION` очищен от HTML; формульные ячейки (`=`, `+`, `-`, `@` в начале) нейтрализуются
апострофом, как и в обычном экспорте. Контакты из постов **не экспортируются** — это данные
для участников, не для выгрузок.

## Отличия от скрейпинга JobSpy

- Легальный доступ: RSS, официальные API, публичные страницы, свой аккаунт — без прокси
  и обхода блокировок.
- Дедуп: одна публикация, найденная на двух площадках, — один лид, а не две строки.
- Свежесть: источники опрашиваются каждые `RADAR_POLL_INTERVAL_SEC` секунд; закрытые
  посты уходят из ленты.
